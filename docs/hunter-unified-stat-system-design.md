# 헌터 스탯 기반 통일 시스템 — 설계도

## 목표와 핵심 컨셉

전투 밸런스 불일치(NPC 시뮬 vs 실제 전투의 단위 괴리)를 근본 해결하기 위해, **NPC 네임드/A급 헌터를 플레이어와 같은 규칙(스탯·직업·스킬·등급·칭호·장비 → 통일 전투력 → BattleUnit)으로 만든다.** 

**핵심 컨셉 — "나 혼자만 레벨업"**: 원작에서 헌터는 근본적으로 성장하지 않는다(성장은 플레이어=성진우의 특권). 따라서 헌터의 대부분은 **확정값(회차 무관 고정)**이고, 변수는 소수다. 이 컨셉이 작업을 "동적 시뮬레이션 구축"에서 "고정 데이터 정의 + 소수 변수 연결"로 가볍게 만든다.

이로써 얻는 것: ①플레이어↔헌터 전투력 비교가 진짜가 됨(통일 척도) ②밸런스 조정 기준 통일 ③향후 헌터 vs 헌터 / 플레이어 vs 헌터 대결 가능(원작 장면) ④밸런스 불일치 원천 해결.

## 1. 헌터의 구성 요소

### 고정 (회차 무관, 수작업 정의 — 시드 데이터로 박음)
- **등급(rank)**: A / S / National. (B 이하는 익명 풀 유지 — 아래 4)
- **스탯**: STR/VIT/AGI/INT/PER/SEN (플레이어와 동일 StatKey).
- **직업(jobId)**: 플레이어 직업 체계 재사용 또는 헌터용 정의.
- **칭호(title)**: 고정 부여.
- **기본 장비**: 시작 장비 고정.
- **스킬**: 헌터마다 고유 스킬셋(플레이어 스킬 체계 재사용). ★신규.
- → 이 값들은 **리셋/회차 변경에도 동일**. 한 번 정의하면 영구.

### 변수 (회차마다 다름)
- **성향(특성, traitId)**: 이미 구현됨(12종, 매 회차 랜덤).
- **상태(status)**: 정상/부상/사망. 이미 구현됨.
- **게이트 획득 장비**: 이미 구현됨(equipmentScore + equipmentItems). 기본 장비 위에 누적.
- **잠재력(potential)**: ★신규. 회차마다 랜덤. 각성 확률을 좌우(아래 3).

### 동적 사건
- **각성**: ★신규. 아래 3.

## 2. 통일 전투력 산출식

플레이어 전투력 = baseStats + equipment + title + skills + shadows + misc.
**헌터 전투력 = baseStats + equipment + title + skills** (그림자 없음, misc 선택).
- 플레이어와 **같은 공식·같은 계수**를 쓴다(combatPower.ts 재사용/공유). 이것이 "통일 척도"의 핵심.
- 헌터 BattleUnit도 플레이어와 같은 변환(`buildHunterBattleUnit` 계열 재사용) → HP/ATK/DEF가 같은 규칙으로 산출.
- → "이진성 전투력 8,000"과 "플레이어 전투력 8,000"이 **같은 강함**을 의미. 비교가 진짜가 됨.

### 몬스터/군주 스케일도 이 기준에 정렬
- 통일된 헌터/플레이어 전투력 척도에 맞춰 몬스터·군주 BattleUnit을 정렬(별도 진단의 "몬스터 곱연산 폭발" 교정 포함). 모두가 한 척도 위에 놓이게.

---

## 3. 각성 시스템 (잠재력 기반)

- **잠재력(potential)**: A급·S급 헌터에게 회차마다 랜덤 부여(National 제외 — 천장이라 각성 무의미). 0~1 또는 등급값.
- **발동**: 헌터가 게이트 클리어 시, 잠재력에 비례한 **낮은 확률**로 각성. (흔하면 "고정 등급" 컨셉이 무너지므로 드물게 — 회차당 0~2명 수준.)
- **효과**: 등급 +1단계(A→S, S→National), 스탯 증가, 스킬 강화. (거창한 변신 아님.)
- **의미**: 원작의 차성호처럼 "무명 A급이 각성해 S급으로" → 회차마다 깜짝 변수. 회차 분산에 또 한 겹.
- 각성은 그 회차 내에서만 유지(회차 리셋 시 원래 고정 등급으로 복귀 — 잠재력 재랜덤).

---

## 4. 범위 (작업량 관리)

- **개별 스탯 유닛으로 만들 대상**: **A급 + S급 + National급** 헌터. 수작업으로 이름·스탯·직업·칭호·기본장비·스킬 정의.
  - 규모: 네임드(S/National) 나라당 4~5명 + A급 나라당 3~18명. 15개국이면 A급 ~100명대.
  - 국가 수를 줄이면(예: 15→10 또는 8) 작업량 더 감소. **국가 수 축소 여부는 사용자 결정 필요.**
- **B급 이하**: 익명 풀 유지(개별화 안 함). 국가 전력 숫자로만 기여. 표시/플레이어 전투 대상 아님.
- **대량 NPC 게이트 시뮬**: 헌터에 스탯을 부여하되, **NPC끼리의 일상 게이트 전투는 "스탯에서 산출된 전투력"으로 빠른 승률 판정 유지**(실제 턴제 아님 — 성능 보존). 
  - **플레이어가 실제 참여하는 전투(군주·러브콜 원정·미래의 헌터 대결)만 진짜 BattleUnit 턴제.**
  - → 데이터는 통일(스탯 기반), 대량 시뮬은 전투력 요약으로 빠르게. 성능 재앙 회피.

---

## 5. 작업 단계 (큰 작업이므로 분할)

**1단계 — 데이터 구조 + 전투력 통일**
- HunterState에 준하는 헌터 스탯/직업/스킬/칭호/장비 구조(또는 NamedHunter 확장).
- 통일 전투력 산출식 적용(combatPower 재사용). 헌터 전투력 = 플레이어와 같은 공식.
- 기존 power 필드를 이 산출식 결과로 대체/연결. NPC 시뮬은 이 전투력으로 빠른 판정 유지.

**2단계 — A/S/National 수작업 정의**
- 각 나라 A급 이상 헌터의 고정 데이터(이름·등급·스탯·직업·칭호·기본장비·스킬) 시드 정의. (국가 수 축소 결정 반영.)

**3단계 — 잠재력 + 각성**
- 잠재력 회차 랜덤 부여, 게이트 클리어 시 각성 발동, 등급/스탯/스킬 상승.

**4단계 — 몬스터/군주 스케일 정렬 + 밸런스**
- 통일 척도에 맞춰 몬스터 곱연산 폭발 교정, 군주/천사 정렬. 목표 곡선(일반 게이트 무난, 군주 협력, 천사 풀팀) 재측정.

**5단계 — (선택) 헌터 대결**
- 플레이어 vs 헌터 / 헌터 vs 헌터 전투(원작 장면). 통일 시스템이라 자연히 가능.

각 단계 후 시뮬 밸런스 회귀 + 통합 스케일 감사 재측정. 코어 무수정.

---

## 6. 결정 필요 사항
1. **국가 수 축소?** 현재 15개국. 유지 vs 축소(예: 10 또는 8). 작업량 직결.
2. **헌터 직업/스킬**: 플레이어 직업 체계를 그대로 재사용? 아니면 헌터용 간소 버전?
3. **수작업 정의 범위**: A급까지 전부 개별 정의(노동 큼) 확정?

## 한 줄 요약
> "나 혼자만 레벨업" 컨셉(헌터는 성장 안 함 → 대부분 고정값)을 적용해, A급 이상 헌터를 플레이어와 같은 규칙(스탯·직업·스킬·등급·칭호·장비 → 통일 전투력 → BattleUnit)으로 정의한다. 변수는 성향·상태·획득장비·잠재력(각성)뿐. 대량 NPC 시뮬은 전투력 요약으로 빠르게, 플레이어 참여 전투만 실제 턴제. 이로써 전투력 비교가 진짜가 되고, 밸런스 기준이 통일되며, 헌터 대결 같은 확장이 열린다.
